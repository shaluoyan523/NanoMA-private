# Implicit Delivery Benchmark

Build a compact delivery package for a small "incident response readiness" utility.

Work only under `shared/implicit_delivery/`.

The final package must include:

- `requirements.md`: concise product requirements and acceptance criteria.
- `constraints.md`: operational constraints, assumptions, and non-goals.
- `design.md`: implementation design informed by the requirements.
- `risk_review.md`: risks, edge cases, and mitigations informed by the requirements and constraints.
- `final_package.md`: integrated delivery summary that references the prior artifacts.

Quality expectations:

- Each artifact should be written as Markdown.
- Each artifact should clearly state which prior artifacts, if any, informed it.
- The final package should be internally consistent and call out unresolved tradeoffs.
- Prefer independent review where useful, but avoid unnecessary work.
- Keep public memory/tags current so collaborators can discover completed work.
- Use query-based status discovery before final synthesis if multiple collaborators are involved.

Completion:

- Submit the final artifact.
- Finish with a concise result describing what was delivered.
